# Checklist — Accessibilité

## Objectif du document
Fournir une checklist réutilisable pour vérifier l’accessibilité des interfaces utilisateur d’Analyse Basket.

## Informations de contrôle
- Date du contrôle : À compléter
- Page ou parcours contrôlé : À compléter
- Contrôleur : À compléter
- Environnement : À compléter
- Navigateur : À compléter
- Statut global : À compléter

## Statuts possibles
- OK
- KO
- Non applicable
- À vérifier

## Navigation
- [ ] Navigation clavier complète sur le parcours contrôlé.
- [ ] Ordre de tabulation cohérent.
- [ ] Focus visible.
- [ ] Aucun piège clavier.

## Formulaires
- [ ] Labels explicites sur les champs.
- [ ] Champs obligatoires identifiables.
- [ ] Messages d’erreur compréhensibles.
- [ ] Messages d’erreur reliés au champ concerné si possible.

## Lisibilité et contraste
- [ ] Contrastes suffisants.
- [ ] Texte lisible.
- [ ] Interface utilisable sans dépendre uniquement de la couleur.
- [ ] Aucune information critique transmise uniquement par couleur.

## Composants interactifs
- [ ] Boutons icônes avec `aria-label`.
- [ ] Boutons d’action avec intitulé explicite.
- [ ] Modales utilisables au clavier.
- [ ] Fermeture des modales possible clairement.

## Vidéo et analyse
- [ ] Limites métier liées à l’analyse vidéo documentées.
- [ ] L’utilisateur comprend qu’une partie du service repose sur une activité fortement visuelle.
- [ ] Les zones non strictement vidéo restent utilisables de manière accessible.

## Messages et feedback utilisateur
- [ ] Les confirmations d’action critique sont compréhensibles.
- [ ] Les erreurs API sont affichées de manière compréhensible.

## Tutoriel et aide
- [ ] Tutoriel utilisateur présent.
- [ ] Raccourcis clavier documentés.

## Responsive
- [ ] Responsive vérifié sur desktop.
- [ ] Responsive mobile/tablette à vérifier si applicable.
